# E09.1 — Sincronización instantánea con webhook de GitHub

## Objetivo
Que el tablero se actualice en segundos al hacer push o tocar una PR, en vez de
esperar al siguiente intervalo de `SYNC_CRON`.

## Alcance
- Ruta `POST /api/webhooks/github` que acepta los eventos `push`,
  `pull_request` y `ping`. Cualquier otro evento responde 202 y se ignora.
- **Firma HMAC obligatoria**: se valida `X-Hub-Signature-256` con el secreto
  `GITHUB_WEBHOOK_SECRET` y comparación en tiempo constante. Sin secreto
  configurado, la ruta responde 404.
- El webhook no sincroniza en la petición: busca los proyectos cuyo
  `owner/name` coincide con el repo del evento y encola su sincronización para
  el worker. Responde 202 enseguida, para no superar el tiempo límite de GitHub.
- Se ignoran los `push` a ramas que ningún proyecto sigue y las acciones de PR
  que no cambian nada del tablero (`labeled`, `assigned`…).
- Varios eventos seguidos del mismo repo se agrupan en una única
  sincronización.
- **Exposición**: hoy el servidor solo es accesible desde la red local y la VPN
  (E08, E11). Hay que decidir cómo le llega el evento: publicar solo esta ruta
  en el proxy, o un túnel/relay. El resto de la API sigue sin exponerse.
- El intervalo del worker se mantiene como red de seguridad por si se pierde
  algún evento.

## Criterios de aceptación
- Tras un push que marca una casilla, la tarjeta cambia en menos de 30 s.
- Una petición sin firma o con firma incorrecta responde 401 y no encola nada.
- Desde fuera de la red solo es accesible `/api/webhooks/github`.
- Diez pushes seguidos al mismo repo producen una sola sincronización.
