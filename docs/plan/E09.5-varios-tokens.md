# E09.5 — Varios tokens de GitHub

## Objetivo
Seguir repos de varios usuarios u organizaciones aunque cada fine-grained token
solo vea los repos de un propietario.

## Alcance
- Se puede configurar **un token por propietario**, más uno por defecto para
  el resto. Por ejemplo `GITHUB_TOKENS=joeljoanlopez:ghp_…,mi-org:ghp_…`,
  manteniendo `GITHUB_TOKEN` como valor por defecto para no romper las
  instalaciones actuales.
- Los tokens viven solo en el entorno, nunca en la base de datos ni en las
  respuestas de la API.
- `GitHubSourceHost` elige el token según el `owner` de cada llamada. La caché
  sigue decorando el puerto y no cambia.
- `GET /api/repositories` junta los repos visibles con todos los tokens, sin
  duplicados.
- Los errores dicen qué propietario no tiene token o cuál ha sido rechazado.

## Criterios de aceptación
- Con dos tokens de propietarios distintos, se pueden dar de alta y sincronizar
  repos de ambos.
- Con solo `GITHUB_TOKEN`, todo funciona como hasta ahora.
- Un token caducado de un propietario no impide sincronizar los proyectos de
  los demás.
